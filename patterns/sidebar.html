Sidebar Navigation

bt-sidebar is the persistent left-column navigator inside u-layout--app. Use it for real page navigation only — not as a filter panel or decorative element. The filter rail on results pages is a plain <aside> — see Facets and Search & filtering, not this component.

Basic structure

Links use Bootstrap .nav-link directly on <a> elements inside the sidebar. The SCSS provides flex layout, gap, and padding — no Bootstrap utility classes needed on the link. Group labels use .bt-sidebar__group-label. Wrap link text in .bt-sidebar__label so it hides cleanly in slim mode.

Badges

Drop a Bootstrap badge directly inside the link. The SCSS positions the badge on the right automatically — no helper wrapper classes are needed. Use badge--total on count badges, include a hidden label for screen-reader context, and keep the visible label on the link. In slim mode a count badge shrinks to a dot; a sidebar link carries no other kind of badge.

Badge colour signals urgency: bg-danger for overdue/errors, bg-warning for items needing attention, bg-primary for neutral counts.

Collapsible — slim mode

Adding .bt-sidebar--slim collapses the sidebar to icon-only width (3rem). Group labels and secondary badges are hidden via CSS; link text and button text are hidden from view but stay in the accessibility tree, so an icon-only link keeps its name. The toggle button updates aria-expanded and aria-label — handled by sidebar-toggle.js, which also enables the link tooltips in this state and disables them again when the sidebar expands. Below xl, the main sidebar starts in slim mode so narrow desktop panes keep the work area primary.

Responsive Work Panes

Backoffice users often work in a narrow desktop pane with another system open beside Biblio. In that range, the main app navigation must stop taking full-sidebar space by default. The list, record, or form in main remains the primary work area.

Behaviour

At xl and above, the sidebar starts expanded.

Below xl, the sidebar starts in bt-sidebar--slim mode.

When the viewport crosses the xl breakpoint after load, sidebar-toggle.js syncs the sidebar to the new range: narrow collapses, wide expands.

The toggle remains available in both ranges. This is a responsive default, not a disabled state.

Why

Curators and reviewers use split-screen setups for queue work, record details, source material, email, and external systems.

At narrow desktop widths, a full navigation rail plus a filter rail leaves the result list feeling like a secondary column.

Pair this with the filter drawer split on result-list pages: app navigation becomes slim, filters move behind an explicit control, and the work list keeps the horizontal space.

js contract
const narrowSidebarQuery = window.matchMedia('(max-width: 1199.98px)');

// initial load
sidebar.classList.toggle('bt-sidebar--slim', narrowSidebarQuery.matches);

// after resizing across the breakpoint
narrowSidebarQuery.addEventListener('change', () => {
  sidebar.classList.toggle('bt-sidebar--slim', narrowSidebarQuery.matches);
});

Issue acceptance criteria

  • The main backoffice sidebar is expanded by default at xl and wider.
  • The main backoffice sidebar is slim by default below xl.
  • Resizing an already-loaded page across the xl breakpoint updates the sidebar state.
  • The toggle button still expands and collapses the sidebar and keeps aria-expanded plus aria-label accurate.
  • Nav links keep their accessible name in slim mode, and tooltips give sighted users the label on hover.
  • Result-list filter drawers do not leave an empty grid column when the facet sidebar is offcanvas.

Implementation notes

Use the existing bt-sidebar--slim modifier; do not add a second mobile/sidebar class.

Keep the breakpoint aligned with Bootstrap xl: 1199.98px max-width for the narrow query.

The prototype handles state client-side. In Raven, consider a server-readable persisted preference so the first paint can match the user's preferred state without a visual jump.

Do not use this pattern for facet filters. Result-list facets use u-main__body--filter-drawer plus Bootstrap Offcanvas.

Layout integration

bt-sidebar is a direct child of u-layout--app placed in the sidebar grid area. The shell handles sticky positioning and scroll — do not add position: sticky or overflow rules to the sidebar element.

The canonical app sidebar lives in templates/partials/main-sidebar.html. templates/biblio-team/curate.html and templates/biblio-researcher/search-researcher.html both use that partial, then set the active item with an @active comment.

Sidebar width is controlled by two CSS custom properties on u-layout--app: --u-nav-sidebar-width (default 13rem) and --u-nav-sidebar-width-slim (default 3rem). Override them on the shell element if a page needs different widths. The narrow default is an initial state, not a lock: users can expand the sidebar with the toggle.

Available classes

Class Element Purpose
bt-sidebar <nav> Base sidebar container. Sets width, padding, and scroll behaviour.
bt-sidebar--bordered Modifier on bt-sidebar Adds a right-edge border. Use for detail-page section navs, not the global app sidebar.
bt-sidebar--slim Modifier on bt-sidebar Collapses to icon-only width (3rem). Hides group labels, link text, and badges.
bt-sidebar--flush Modifier on bt-sidebar Removes horizontal padding. Use when links provide their own internal spacing.
bt-sidebar__toggle <button> Collapse/expand trigger. Toggles bt-sidebar--slim on the parent nav.
bt-sidebar__group-label <p> Section heading inside the sidebar. Hidden automatically in slim mode.
bt-sidebar__label <span> inside .nav-link Link text. Must be wrapped in this span so slim mode can hide it while keeping the icon visible.

Bootstrap recommendations

The sidebar uses Bootstrap's .nav-link on <a> elements directly. The SCSS scopes all flex layout, spacing, and badge alignment inside .bt-sidebar — no Bootstrap utility classes needed on the links themselves.

Active state

Set both aria-current="page" and class="nav-link active" on the active link. aria-current is what screen readers use; .active handles the visual background. In server-rendered templates, set both explicitly.

Tooltips

Add data-bs-toggle="tooltip" data-bs-placement="right" title="…" to every link, repeating the visible label word for word. sidebar-toggle.js creates the tooltips at page load and enables them only in slim mode, so an expanded sidebar does not repeat a label the reader already has.

The tooltip is not the accessible name. Bootstrap moves title to data-bs-original-title the moment it initialises, and only writes an aria-label when the element has no text of its own — which these links do have. The name comes from .bt-sidebar__label, which slim mode hides visually and keeps in the accessibility tree. Do not add aria-label to a sidebar link: it would replace the visible text with a second string to keep in sync.

Mobile — consider Offcanvas

Bootstrap's Offcanvas handles mobile drawers that slide over content. If the sidebar needs to become a drawer on small screens, wrap it in an Offcanvas body rather than building a custom mobile variant. bt-sidebar styles remain usable inside the Offcanvas body with no changes.
