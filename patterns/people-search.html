People search

An inline search that resolves a person from the PersonIdentity index. One search, one rich result row, two selection shapes: click-to-select in a form (deposit add-author, curate detail) and checkable rows in a panel (author filter editor, query builder). Not a modal — the results list floats directly below the input, over whatever follows it.

Empty — before typing

The input is focused. No results list yet. The hint below the input explains what the field searches across. The hint is the widget's live region: it exists in the DOM from the start, and it announces the result count, the searching state and the no-results message.

Results — query "doe"

Results appear in a bordered list below the input. The list is an overlay: it floats over the form beneath, so results appearing or clearing never push the form around. The query term is highlighted in the name with <mark>. Each row shows the affiliation, department, active years, ORCID and UGent ID the identity carries. External people show "External" as affiliation. Keyboard: ArrowDown moves from the input into the list and between rows, Enter or Space selects, Escape returns to the input. The hint announces the result count.

Selected

After the user clicks a row, the list collapses to show only the selected person — name and affiliation, the rest of the metadata drops. The row gets .is-selected and aria-selected="true" — blue background, checkmark on the right. The input value updates to the person's name and the hint clears. The user can clear the selection to search again.

No results

When the query returns nothing, the results list hides and the hint announces the no-results message — the message lives in the widget's live region, never inside the empty listbox. No illustration, no secondary action: the user refines the query, or in a deposit context falls back to "Add as external author".

Click-to-select rich rows — single select in a form

Two hosts pick one person at a time: the deposit flow's add-author form and the backoffice curate detail. The widget (data-people-search, driven by people-search.js) sits in the form without panel chrome or checkboxes. Clicking a rich row is terminal: the floating list closes, the person lands in the confirmation slot, and the row's data-id and data-name fill the form's hidden fields. The role select stays beside the widget, because a role belongs to one person. The clear button restarts the search. The "Not in the system? Add as external author" fallback exists only in these hosts, where you are creating an unlinked contributor on a work.

Checkable rich rows — multi-select in a panel

Two hosts pick several people at once: the works-page author filter editor and the query builder's Person condition. There each row is a plain Bootstrap form-check inside a bt-panel__body--checklist, in the search-first shape. The checkbox replaces the user icon. The label carries the same rich row content — people-result__name with <mark>, the people-result__meta items — because two people with the same name must be tellable apart before you tick one. The footer button names the outcome: Apply replaces the filter's set, Add appends query builder tokens.

Defined in assets/scss/patterns/_booktower-people-results.scss.

Class Element Purpose
.people-results div[role="listbox"] Scroll container for result rows. Bordered, rounded, max-height with overflow-y auto.
.people-result div[role="option"] A single person row. Flex, cursor pointer, border-bottom between rows.
.people-result.is-selected — Blue background. Add aria-selected="true" at the same time.
.people-result__icon span Icon column, flex-shrink-0, muted colour.
.people-result__name div Person's display name. Contains <mark> for query highlights.
.people-result__meta div Flex row of metadata items, xs text, muted colour.
.people-result__meta-item span One metadata token (affiliation, dept, years, ORCID). Inline-flex with icon.

Behaviour

  • Search fires after 2 characters with a 300ms debounce.
  • In production: hx-get="/people/search?q=" returning the people-search-results.html partial. While the request is in flight, an htmx-indicator span with aria-live="polite" shows "Searching…".
  • /people/search returns UGent people and the external people the index already holds — one search, both kinds, wherever a person is picked. A person in no index is not searchable, which is what the deposit form's external fallback is for.
  • In the prototype: the PEOPLE array in assets/js/people-search-stub.js stands in for the server.
  • Clicking a row updates the input value, collapses the list to the selected state, and stores the person's data-id and data-name for the filter chip or form submission.
  • An unlinked (external) author is valid. The no-results state should lead to the "Add as external author" fallback if present in the host context (deposit form), not block submission.
