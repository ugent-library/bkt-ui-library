Pagination

Pagination itself is plain Bootstrap (ul.pagination). What this page pins is the bar around it: a bt-toolbar carrying the page links and the result count on the left, and the reading controls — page size, sort, more actions — on the right.

Results bar

The canonical composition, at the head of a result list (public-works). Left says where you are, right says how you read. The count sits beside the pagination but outside the <nav> — it is a status, not a link — and carries aria-live="polite" so a page or filter change is announced. Everyone reads the same string, at every width. Sort options are a stub: the sort set is still open.

Page range and states

The range is compact: first, current ±1, last, with … for the gaps. An inert item is a <span class="page-link"> inside li.page-item.disabled — never a disabled <a href>, which stays clickable and focusable (Bootstrap: disabled and active states). The arrows are if-chevron-left / if-chevron-right, inheriting the link’s size. The <nav> labels in the demos below carry a suffix only so several bars can sit on this one kit page — for a real page, take the label from the ARIA table.

Repeated bar — long list

A long list repeats the bar under the results so you can page on without scrolling back. The top bar owns the live region; the bottom one repeats the same text as plain status. Each <nav> gets a distinguishing label — Results pagination (top) / (bottom) (rule A5). Live on the researcher and project detail pages, where the top bar carries the controls and the bottom bar only pages.

A–Z browse bar

Browsing an alphabetical index reuses ul.pagination for the letter row: same affordance, same keyboard behaviour, no second component. It is a browse control, not pagination, so it gets its own label and stays full size — the letter row and the pagination under it match each other. A letter with no entries is disabled. Live on public-researchers.

ARIA — what each part is named

The <nav> label answers “which pagination is this?”. House rule A5 wants every <nav> on the page distinctly labelled, so the label depends on how many there are:

SituationLabel
One list, one bar aria-label="Results pagination"
One list, a bar above and below it "Results pagination (top)" and "Results pagination (bottom)" — position is what distinguishes them, and it tells a screen-reader user where they landed
Two different lists on one page (detail-page tabs, a letter index and its pages) name what is paginated, not where it sits: "Research output pagination", "Records pagination", "Pages within letter D"

The rest is fixed, whatever the situation:

PartCarriesWhy
The count, on the bar at the head of the list aria-live="polite" Paging, sorting and filtering all rewrite it; polite announces the new range without interrupting. Not role="status" — the house rules keep that for confirmations.
The count, on a repeated bar below the results nothing Same string, already announced by the bar above. Two live regions announce the same change twice.
Numbered page links and browse letters nothing beyond their text “2” is a name, and the labelled <nav> plus the list around it are the context WCAG 2.4.4 asks for at AA. Naming them "Page 2" so they stand alone in a links list is 2.4.9 — AAA, above our target. Do not add it.
Current page link aria-current="page" li.page-item.active is the visual half; aria-current is the spoken half.
Arrow links aria-label="Previous page" / "Next page", and aria-hidden="true" on the icon An icon has no accessible name. The label sits on the link, never on the <i>.
Inert arrows and empty letters (span.page-link) nothing Not focusable, no text, so nothing is announced. aria-disabled would describe a control that is not there.
The … gaps aria-hidden="true" on the <li> A visual shorthand for skipped pages, not a destination.
Page size and sort <select> <label class="visually-hidden"> The chosen option (“50 per page”) reads as the value; the label says what the value is for.

Rules

  • The <nav> wraps the <ul> only. The count is a sibling in bt-toolbar__left. Inside the nav it would be read as part of the navigation.
  • The count is one string, visible at every width — Showing 1–50 of 879 results. No hidden copy: visually-hidden would hide “Showing” from sighted readers too, and pairing it with d-none d-md-inline-block removes it from the accessibility tree below md instead of revealing it. The bar wraps before the sentence does.
  • Inert items are <span class="page-link"> in li.page-item.disabled — arrows at the ends of the range, letters with no entries, the … gaps. The gaps also take aria-hidden="true": they are a visual shorthand, not a destination.
  • Arrows are icons — if-chevron-left / if-chevron-right, aria-hidden, sized by the link they sit in. The link carries aria-label="Previous page" / "Next page": an icon has no accessible name of its own.
  • The current page is li.page-item.active + aria-current="page" on the link. It keeps its href — a copyable URL for where you are.
  • Size follows the bar. A results bar uses pagination-sm; a browse index and its letter pages stay full size. One size per bar, and the two bars of one list match.
  • No mb-0 on ul.pagination. The base reset already zeroes list margins.
  • Every child of __left / __right is a bt-toolbar__item. For a form-select it is load-bearing: as a direct flex child its width: 100% collapses every select to one shared width and the longest label truncates.
  • Narrow screens stack, they do not scroll. The bar wraps in reading order — pagination, count, then the controls, which wrap among themselves below roughly 600px.
  • Changing sort or page size returns to page 1 — a page number only means something against a fixed order (see Search and filtering).
