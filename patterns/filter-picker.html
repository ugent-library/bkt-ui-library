Filter picker & editor

One connected interaction: a grouped filter menu (the picker) and an inline editor panel that opens when a filter is chosen, with applied filters shown as chips. Live on the public works page and the researcher / project directories, all driven by one engine — filter-bar.js.

How it works

The full flow, end to end:

  1. User clicks Add filter → Bootstrap dropdown opens showing the picker
  2. User clicks a filter item (e.g. Organization) → dropdown closes, editor panel appears over the result list
  3. User sets a value → clicks Apply → editor closes, a chip appears in the active filter bar
  4. User clicks a chip → editor reopens pre-populated for editing
  5. User clicks × on a chip → filter removed

Wired by filter-bar.js — one engine, and no filter set inside it. A bar announces itself with data-filter-bar="<prefix>"; each picker button carries its own definition (data-filter-label, data-filter-type, and then data-filter-options, data-filter-panel, data-filter-placeholder, or data-filter-yes/data-filter-no), so the picker list is the filter set. Chips are client-side only in the prototype.

The examples below are written out. The running bar clones the same shapes from templates/partials/filter-editor-templates.html, reads its option lists from templates/partials/filter-option-lists.html, and clones a picker filter's body from the panel partial its button names. Each partial is included once per page carrying a bar that uses it.

Every editor carries the same three actions: Apply, Cancel, and Remove filter pushed right with ms-auto. Remove is drawn whether or not the filter is applied yet — one footer, one shape, so the panel does not change under you between a first open and a re-open. Removing something that was never applied does nothing, which is what Cancel does anyway.

Picker

A short, flat list of [data-filter] items in a bt-dropdown-scroll — no search input on the picker itself, because each filter set is small enough to scan. The researcher directory offers Organization; the project directory offers status and a year range, and no Organization, because project participation is deferred in raven's data contract; public works uses the search-it set — Person, Organization, Project, Keywords, Identifier (grouped with dropdown-header labels). Searching happens inside the editor, not the picker.

Picker — selected / applied items

When a filter is already applied (or is the one currently being edited), its picker item is marked with Bootstrap's .active state plus a trailing check icon. Reopening the picker then shows at a glance which dimensions are in play — without this, an applied filter looks identical to an unused one. Driven by aria-current="true" for assistive tech.

Selected / applied items

The .active fill is recoloured via --bs-dropdown-link-active-bg: var(--bt-blue-200) and --bs-dropdown-link-active-color: rgba(var(--bs-dark-rgb), 1) (text-dark) — a global --bs-dropdown-* override in foundation/_bootstrap-overrides.scss.

filter-bar.js toggles this from the active-filter state on every apply / remove / clear, and while a filter is being edited. Picking an item closes the picker and opens the editor, so the highlight is what you see when you reopen Add filter.

Editor — checklist

Used for pick-from-a-set values — the works Keywords filter. Person, Organization and Project pick records instead — below. Multiple selections produce a chip like "Climate change +2". The .bt-panel__body--checklist container scrolls when long, and lists over 8 items get a search-within box above the list to filter the options as you type.

Editor — picker

The works Person, Organization and Project filters pick records, so each opens its entity’s picker panel: two records share a label, and the row is what tells them apart. The query builder’s conditions clone the same panels. The person panel is canonical at people search — checkable rich rows; the organization and project rows are stand-ins, their design task logged in the panel partials.

Apply replaces the set. An applied row is held by identifier, never by the label on screen.

Search-within matches the whole row, so an ORCID or a department code finds a person as a name does. That is intended: someone holding the identifier should not need the spelling.

Editor — boolean

Used for yes/no filters — the project directory's Status is the one that is live; current-or-alumni and has-public-research-output are the same shape. Plain .form-check radios in a .bt-panel__body--boolean; the two labels come from the picker button's data-filter-yes and data-filter-no.

Editor as overlay

The editor panel floats over the result list instead of pushing it down. The filter bar and panel are wrapped in a position-relative container; the panel (#wf-filter-editor / #rdir-filter-editor / #pdir-filter-editor) gets position-absolute top-100 mt-2, and filter-bar.js sets its left offset so it drops under whatever opened it (the Add-filter button or the chip), clamped to the viewport so a squeezed layout never pushes it off-screen.

The popover z-index (and a min-width floor for narrow anchors) lives on .bt-panel itself — Bootstrap's z-3 utility maxes at 3, which ties with the active .page-link in pagination.

Active chips

Applied filters surface as chips — the visible output of the picker/editor flow. The standard is the editable split chip: the label reopens the editor, the × removes it — two clickable badges (outline, squared) joined with .filter-chip-group. While a chip's editor is open both halves add .active (blue fill) and the label carries aria-current="true". Display-only summaries use a soft badge text-bg-primary-light.

The assembled bar

The whole bar in one bt-toolbar: the active-filter chips (the readout), the Add filter picker, and Clear all, together. Inlined per page (works, researchers, projects) — identical but for the picker items and id prefix — and wired by filter-bar.js. Use Show HTML for the markup; the required ids are in the wiring reference below, and the editor panel (see the editor sections above) sits in the same position-relative wrapper so it can overlay the results.

Wiring reference

Each bar prefixes its IDs — wf- for works, rdir- for researchers, pdir- for projects — all driven by filter-bar.js. The set below is shown with the rdir- prefix; the engine exits silently for a bar if any are missing.

ID / attribute Element Purpose
id="rdir-add-filter-dropdown" Dropdown wrapper div Outside-click close handler
id="rdir-add-filter-btn" Bootstrap dropdown trigger button Closed programmatically when an item is selected
id="rdir-filter-picker-list" .bt-dropdown-scroll Contains the [data-filter] items
data-filter="<key>" Each button.dropdown-item The filter’s key. Its label, type and options ride on the same button
id="rdir-filter-editor" div.bt-panel.bt-panel--wide (hidden by default) Editor panel — the engine renders into this and shows/hides it
id="rdir-active-chips" div[role="group"] Chip output — the engine renders and manages chips here
id="rdir-clear-all" button (hidden by default) Shown when chips are active; resets all filters on click
