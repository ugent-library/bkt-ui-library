Work card

The primary list unit for research output. Public cards are the minimum readable form; backoffice cards extend the same grammar with workflow state, responsibility, administrative metadata, and actions.

Shared card grammar

Backoffice cards are extensions of the public card, not a separate component. Every card uses bt-work-card with the same structural regions: bt-work-card__header, bt-work-card__body, and optional bt-work-card__footer.

States, access, and actions

Backoffice cards use Raven status and visibility vocabulary. The old labels Biblio public, Biblio withdrawn, Biblio draft, and Locked are not part of the new card model.

Status badge recipe

Draft Private Submitted Public Returned Public Reviewed Public Retracted

Status, record visibility, and record condition sit next to each other because they answer different questions: where the work is in the workflow, whether the record is publicly visible, and whether the record carries a trust-changing condition such as retraction. Visibility is always visible text, never an icon alone.

Action placement

The top-right action row holds the immediate action for this user and state, plus a compact more-actions control where needed. Curator and reviewer cards also use the bottom quick-links row for utilities: view record, full texts and files, public record, DOI, WoS, PubMed, and Altmetric.

Backoffice cards

Backoffice cards extend the same card. They add Raven status and visibility, denser scan lines, responsibility blocks, projects, related-record counts, audit trail, and role-specific actions. Journal articles, datasets, and software need golden examples because the shared grammar stays stable while the scan line and metadata payload change by type.

Parity checklist

Use this checklist when writing Raven issues from the prototype. Old backoffice is parity evidence; Raven vocabulary and model win.

Must keep

  • Same card component and regions as the public card
  • Raven deposit status plus visible record visibility
  • Backoffice access wording
  • Three contributors plus remaining count
  • Projects on backoffice cards
  • Related datasets/publications as backoffice counts
  • Responsibility blocks for researcher and curator work
  • Biblio ID copy, audit trail, and system update where present
  • DOI, WoS, PubMed, Altmetric, files, and public-record links
  • Dataset parity: access, licence, identifier, format, related publications
  • Software candidate display: repository/archive, identifier, licence, platform or language, and related-record counts; software version is a later modelling question
  • Retraction indicator on public, researcher, proxy, curator, and reviewer cards

Still open
