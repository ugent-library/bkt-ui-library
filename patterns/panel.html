Patterns

Panel

A generic popover panel — a titled header, one or more bodies, an optional actions footer — shown inside a dropdown or overlay. Two bodies stack into the search-first shape: a search field pinned at the top, a scrollable checklist below. The filter editor is the same chrome with an Apply/Cancel footer.

Anatomy

bt-panel wraps a bt-panel__title, one or more bt-panel__body blocks, and an optional bt-panel__actions footer. Each body draws its own top border, so stacking two gives the search-first divider for free: a plain body holds the search field, the bt-panel__body--checklist below it takes the option rows and scrolls past ~240px. Rows are plain Bootstrap form-check. bt-panel--wide fixes the width at 480px — the list body is swapped as you type, and a content-sized panel would resize with it.

Add-to-list picker — search-first

Add to list

Typing filters the checklist; ticking a box adds or removes the work and leaves the panel open. One field searches and names — there is no separate "new list" field.

Create from the search field

When the typed name matches none of your lists, the checklist body holds a create row instead: naming a new list is the same keystrokes as looking for an existing one. The row is a real form — a submit button and a hidden name carrying the typed value — server-rendered, because the server is what knows whether anything matched.

With no lists there is nothing to search, so the create form is the whole body (bt-panel__body--form). Creating the first list returns the picker with that list ticked.

In a dropdown

On result cards the panel is the menu of a Bootstrap dropdown: bt-panel bt-panel--wide on the .dropdown-menu with p-0, and data-bs-auto-close="outside" on the toggle so ticking a box doesn't close it. HTMX drives the three jobs — hx-get re-renders the checklist, hx-put / hx-delete write membership with hx-swap="none" so the typed query survives, hx-post creates. Mirrors raven's AddToListComponent.

The search field triggers on input, never keyup: the field's own ✕ fires input and search only, so on keyup the list stays filtered after a clear.

Live: type to filter, clear to get the list back. The demo renders the menu open and in flow — drop show position-static in real usage; the kit clips absolutely-positioned popups.

A template writes only the toggle and an empty menu — the panel above is a fragment the server returns on first open, per record, the way raven does it. hx-* URLs are stubs.

<div class="dropdown">
  <button type="button" class="btn btn-ghost btn-sm dropdown-toggle"
    data-bs-toggle="dropdown" data-bs-auto-close="outside" aria-expanded="false"
    aria-label="Add to list: <record title>"
    hx-get="/lists/panel?work=s01" hx-trigger="click once"
    hx-target="#atl-s01-panel" hx-swap="innerHTML" hx-indicator="#atl-s01-loading">
    <i class="if if-bookmark-line" aria-hidden="true"></i> Add to list
  </button>
  <div class="dropdown-menu dropdown-menu-end p-0 bt-panel bt-panel--wide" id="atl-s01-panel" role="dialog" aria-label="Add to list">
    <p class="htmx-indicator p-3 mb-0 text-muted small" id="atl-s01-loading" aria-live="polite">Loading your lists&hellip;</p>
  </div>
</div>
