Query builder

Advanced search for building a shareable research set. Each condition keeps its field, operator, and value visible.

The dialog is a URL state

The dialog gives realistic multi-row queries a focused, wide workspace while the result list remains visible as context. The container decision is recorded in docs/decisions/DD-001-advanced-search-dialog.md.

Opening adds &advanced=1; closing removes it. Reload and Back preserve the expected state. Shared links keep the query but omit advanced=1.

The condition row

A row reads left to right: field, optional qualifier, operator, value, and actions. The operator determines the value control. Person, organization, and project conditions use record pickers rather than free text. Every control has a row-specific accessible name.

The states

The works template owns the complete states:

  • builder-full-query — a realistic assembled query.
  • builder-empty — a first visit.
  • builder-one-condition — a query opened with one existing scope.
  • builder-or-group — a one-level OR group.
  • builder-no-results — a query with no matches.

The count, and the one exit

The submit reports the live approximate count through aria-live. Complete conditions update the URL immediately, so Show results, Escape, and Close leave the builder without applying or discarding a pending draft.

When a facet cannot express the condition

A condition can express a negation, range, or pasted batch that a facet cannot. The facet reports that it is controlled by advanced search and links back to the condition. See the facet-set-in-builder state; the rationale lives in docs/wip/QUERY-BUILDER-ISSUE-05-dialog.md.
