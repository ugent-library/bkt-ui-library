Patterns

Layout shells

Two shells cover public pages and backoffice applications.

The two shells

Public pages use normal document flow. App pages use fixed regions with independent scrolling and may add navigation or task panes.

u-layout--public

Use for public search, detail, and landing pages. Content flows normally inside Bootstrap containers.

u-layout--app

Use for backoffice lists, details, and workflows. Add a split body only when the page has a left internal pane.

Public layout

Public pages use shared region names inside normal page flow.

html
<div class="u-layout--public" data-surface="public">
  <header class="bt-navbar">...</header>

  <main id="main-content">
    <div class="u-main__header">
      <div class="container">...</div>
    </div>

    <div class="u-main__body">
      <div class="container">...</div>
    </div>

    <div class="u-main__footer">
      <div class="container">...</div>
    </div>
  </main>
</div>

App layout

Canonical split-shell markup for backoffice pages. Omit regions the page does not need.

html
<div class="u-layout--app" data-surface="backoffice">
  <header class="bt-navbar">...</header>
  <nav class="bt-sidebar" aria-label="Section navigation">...</nav>

  <main id="main-content">
    <div class="u-main__header">...</div>

    <div class="u-main__body u-main__body--split">
      <aside class="u-main__sidebar u-main__sidebar--border-right">...</aside>

      <section class="u-main__content">
        <div class="u-main__content-header">...</div>
        <div class="u-main__content-body">...</div>
        <div class="u-main__content-footer">...</div>
      </section>
    </div>

    <div class="u-main__footer">...</div>
  </main>

  <aside class="u-main__panel" aria-label="Contextual actions">...</aside>
</div>

Page Regions

u-main__header, u-main__body, and u-main__footer are the page-level regions inside main.

Split Body

u-main__sidebar and u-main__content belong inside u-main__body u-main__body--split.

Right Pane

u-main__content-body is the scrolling pane. u-main__content-header and u-main__content-footer stay fixed around it.

App anatomy

The main region has a consistent stacking order for fixed and scrolling content.

Stacking order

.u-main__header optional fixed page header
.u-main__sidebar optional left pane
.u-main__content-header optional right-pane header
.u-main__content-body required scrolling pane body
.u-main__content-footer optional right-pane footer
.u-main__footer optional fixed page footer

Variants

Single-Column Body

Use a plain u-main__body when the page does not need an internal left pane.

<div class="u-main__body">
  <section class="u-main__content">
    <div class="u-main__content-body">...</div>
  </section>
</div>

Split Body

Use u-main__body--split only when a left body sidebar is present.

<div class="u-main__body u-main__body--split">
  <aside class="u-main__sidebar">...</aside>
  <section class="u-main__content">
    <div class="u-main__content-body">...</div>
  </section>
</div>

Filter drawer split

On backoffice result lists, the facet pane becomes a drawer below xl. Other split pages keep the ordinary pane.

html — backoffice result list
<div class="u-main__body u-main__body--split u-main__body--filter-drawer">
  <aside class="u-main__sidebar u-main__sidebar--border-right offcanvas-xl offcanvas-start"
    tabindex="-1" id="result-filters" aria-label="Filter by">
    <div class="offcanvas-header d-xl-none border-bottom">
      <h2 class="h5 mb-0">Filters</h2>
      <button type="button" class="btn-close" data-bs-dismiss="offcanvas"
        data-bs-target="#result-filters" aria-label="Close filters"></button>
    </div>
    <div class="offcanvas-body flex-column p-0">
      <div class="p-3">... facet fieldsets ...</div>
    </div>
  </aside>

  <section class="u-main__content">
    <div class="u-main__content-header">
      <button type="button" class="btn btn-secondary btn-sm d-xl-none"
        data-bs-toggle="offcanvas" data-bs-target="#result-filters"
        aria-controls="result-filters">
        <i class="if if-filter-3-line if--sm" aria-hidden="true"></i>
        Filters
      </button>
      ... search, active filters and readout ...
    </div>
    <div class="u-main__content-body">... result list ...</div>
  </section>
</div>

Keep the trigger in the result-pane header. Bootstrap owns the Offcanvas interaction; Booktower only changes the split grid. See docs/UI-LAYER.md.
