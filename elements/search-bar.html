Listing / results-header search

The canonical search form in every public listing header — research output, researchers, organizations, projects. Square .input-group-lg (not the hero pill), an autocomplete .bt-suggest-panel overlay, and the full combobox ARIA wiring. The structure is identical on all four pages; only the scope varies — the placeholder and aria-label copy, the action, and the behaviour hook (works carries hx-* for omni-suggest; the directories carry data-directory-search for client-side typeahead). IDs are the generic q / suggest-wrapper / suggest-panel on every page.

Listing header, query present — .input-group.input-group-lg + .bt-suggest-panel

The × clears the query and leaves the filters standing. The field's border encloses it, and Search stays a segment beside the field. An empty box carries hidden on the same anchor, and the field reclaims the space. The chips carry their own Clear all filters, so each clear does only what sits next to it. Rule 2 in docs/SEARCH-AND-FILTERING.md holds both.

Every box on the public surface takes this ×, and a field that carries it shows no other: where the field is type="search", WebKit and Blink would draw a clear of their own, and the system suppresses it. One act, one shape, on every box.

The clear is an anchor:

  • btn btn-ghost bt-search-clear, placed before the submit button
  • aria-label="Clear search" and an if-close icon
  • an href pointing at the current URL minus q, so the filter params ride along
  • or, where the box filters a list in place and there is no address to go to, a <button type="button"> — search-clear.js empties the field and the list re-filters

Rule: scope varies, structure does not. When adding a fifth listing surface, copy this skeleton verbatim and change only the copy, the action, and the one behaviour hook. Do not rename the IDs — suggest-panel.js binds #q / #suggest-panel / #suggest-wrapper; directory-search.js binds structurally via [data-directory-search].

Compact / toolbar search — backoffice

The compact variant for inline filtering inside a .bt-toolbar — filtering a list, searching within a deposit, live-filtering. Bootstrap .input-group.input-group-sm with .form-control-search. Used in the backoffice overview; not a public-discovery bar. It takes the same clear one size down: bt-search-clear reads the group's size, so a compact field gets a smaller circle and nothing else changes.

Compact — .form-control-search

What the modifier does — and what it leaves alone

Bootstrap's .input-group provides: flex layout, border joining between input and button, and the .input-group-lg / .input-group-sm sizing scale.

.input-group--hero makes the bar the field: the bar carries the border, the radius and — on :focus-within — the focus ring as one unit, and the input inside it goes transparent and ringless. Every control sits in the bar in flow, so a second control never lands on the first and typed text never runs under either.

Both shapes take bt-search-clear. In the hero the flow already keeps the × clear of the text; in the listing box the field reaches under the × and reserves the space as padding, because there the border is the input's own and Search sits outside it.

Accessibility notes

  • Wrap in <form role="search"> with a distinct aria-label so screen reader users can jump to the search landmark directly.
  • The <label> must exist in the DOM even if visually hidden. placeholder alone is not a label.
  • Use type="search" for a standalone search field. When the field is an ARIA combobox, use type="text" with inputmode="search" so the combobox contract remains valid while mobile browsers still show a search-optimized keyboard.
  • The :focus-within ring surrounds the entire pill — individual element outlines are suppressed to avoid a double ring. The ring meets WCAG 2.2 AA contrast requirements.
  • The button must be type="submit" so the form submits without JavaScript. action on the <form> is the no-JS fallback.
  • When wiring to HTMX live search, add hx-get on the input and a paired hx-indicator with aria-live="polite".

When to use this vs the toolbar search

Use .input-group--hero when search is the primary action on the page and deserves visual prominence — homepage hero, a dedicated search landing page, or above a full-width result list.

Use the compact .form-control-search inside a .bt-toolbar for inline filtering in the backoffice — filtering a list, searching within a deposit, live-filtering a dropdown. See the Compact / toolbar search demo above.
